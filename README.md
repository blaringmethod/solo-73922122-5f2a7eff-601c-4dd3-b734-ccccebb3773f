# 期货连续合约结算价系统

把多个合约的期货结算价，按固定换月计划统一到**指定基准日的连续合约口径**。
Flask + SQLite 单体应用，Docker Compose 一键启动。

## 口径定义

- 合约序列：一个**初始合约**（`ord=0`）+ 每次换月启用的新合约（第 k 次换月 → `ord=k`）。
- 换月价差：取**切换日前一交易日**的 `新合约结算价 − 旧合约结算价`（单位：整数分）。
- 某日 d 的连续价（基准日 B，B 不早于查询结束日）：

```
连续价(d, B) = 当日在用合约结算价
             + Σ { 各次换月价差 | d < 切换日 <= B }
```

- 当日原价缺失 → 连续价留空，注明缺哪个合约哪天的原价。
- 区间内某次换月缺报价 → 连续价留空，注明**最早**缺价换月及其待补的合约/日期。
- 连续价**实时计算、不落库**；改价不逐日回写。

## 查价区间缓存（网页与 CSV 共用）

同一段行情换基准日不再重读逐日原价。取数缓存是**单槽**的，只保留最近一个查价区间：

- **缓存内容（稳定部分）**：区间内每个交易日的在用合约、当日原价，以及切换日落在
  `(d, end]` 的“稳定窗口”换月价差和。这些数据一旦被区间内变更影响，缓存立即作废。
- **不缓存的尾部**：切换日落在 `(end, base]` 的换月。命中时按本次基准日读取**当前库**
  最新的 `rolls`/`bit_sums` 现算（切换日索引反向定位 + Fenwick，O(log n)）。
- **命中条件**：区间 `(start, end)` 与缓存相同，且缓存构建版本之后没有影响本区间的变更。
  命中时 `prices` 表**零读取**；整次取数读取的换月及索引记录数至多
  `3 + 2·⌈log₂(n+1)⌉`（n=换月次数），与区间天数无关，随换月次数只对数级增长。
  缓存行本身随区间天数线性增长，但那是缓存数据，不是逐日原价重读。
- **失效规则**（由 `change_log` 版本判定，不靠人工清缓存）：
  - 区间内交易日的报价补改/更正 → 该区间缓存作废，按当前库重建；
  - 补改只联动**区间末日之后**的换月（参考日 `pre_date > end`）→ **缓存仍命中**，
    按本次基准日和最新价差出数，缺价时沿用原提示规则；
  - 交易日历或换月计划变更（`scope='config'`）→ 全部缓存作废，
    取数与按当前库直接查询完全一致。
- **并发正确性**：每次网页查询/下载都在同一个只读快照事务内完成，只看到同一已提交状态。
  建缓存期间行情员仍可补改报价；缓存发布在独立写事务中复核版本号，发现构建期间已有
  新提交就放弃发布并在新快照重取——晚算完的旧缓存不会供新请求使用
  （响应头 `X-Cache-Status`：`hit` / `miss` / `miss_stale`，取数页同步展示）。

## 数据结构与复杂度

| 表 | 作用 |
|---|---|
| `calendar` | 交易日历 |
| `contracts` | 初始合约及每次换月启用的合约（`ord` 即启用次序） |
| `rolls` | 固定换月计划：切换日、前一交易日、新合约、价差（缺报价为 NULL） |
| `prices` | 按合约 + 交易日登记的整数分结算价（联合主键，重复提交即更正） |
| `bit_sums` | 换月价差的 **Fenwick 树**辅助表 |
| `change_log` | 写事务变更版本日志（`config` 全量作废 / `range` 按变更交易日判定） |
| `range_cache` / `range_cache_rows` | 单槽查价区间缓存（元信息 + 逐日稳定部分） |

- 价差区间求和、单点更新均为 **O(log n)**（n=换月次数）；辅助记录数 ≤ n，随换月次数只对数级增长。
- 单笔报价更新：写 1 行 `prices` + 至多重算 1 个价差（前一交易日唯一）+ Fenwick 单点 O(log n)
  + 1 行 `change_log`，在一个 `BEGIN IMMEDIATE` 事务内**原子提交**，原价、受影响价差、
  变更版本一起生效；保存失败整体回滚，预期计算结果仍随返回值可供展示。
- 一次取数在一个只读快照事务内完成，只看到同一已提交状态（SQLite 读快照）；
  缓存命中时不读 `prices`，换月/索引记录读取至多 O(log n)。

## 快速开始（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

数据库持久化在宿主机 `./data/continuous.db`（含 WAL 文件）。

## 本地运行（无 Docker 时）

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
export CONT_DB_PATH=$(pwd)/data/continuous.db
python -m flask --app app.app run --host 0.0.0.0 --port 8000
```

## 使用流程

1. **交易日历**：每行一个 `YYYY-MM-DD`，全量替换保存。
2. **换月计划**：填初始合约代码，逐行添加「切换日 + 当日启用的新合约」后保存。
   切换日必须在交易日历内且严格递增；已有报价后禁止整体重建（防历史错配）。
3. **报价补录/更正**：选合约、交易日，填整数分价格。重复提交即更正；
   若该日是某换月的价差参考日，同事务自动联动重算价差。
4. **连续价取数**：选开始日、结束日、基准日（不得早于结束日）→ 查询 / 下载 CSV
   （UTF-8 BOM，Excel 直开不乱码；缺价行连续价列留空并附说明）。
   首次取数构建区间缓存，同区间换基准日、网页与 CSV 之间直接命中；
   取数页与响应头 `X-Cache-Status` 会标注 `hit` / `miss` / `miss_stale`。

## 待做 / 已知边界

- `change_log` 目前只追加不清理，长期运行会线性增长；缓存判定只看版本差，
  后续可在确认所有缓存版本都新于某版本后做安全归档（当前数据量下无压力）。
- 缓存为单槽设计（按需求只保留最近一个查价区间）；若未来要支持多区间并行热查，
  可把 `cache_id` 扩为多键 LRU，失效判定逻辑不变。
- 绕过应用直接改库（如手工 SQL 改 `prices`）不会写 `change_log`，
  需在同一事务里补一条变更记录，否则缓存不会感知——正常页面操作无此问题。
